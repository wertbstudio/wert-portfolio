# WERT — портфолио веб-разработчика

Адаптивный сайт без внешних npm-зависимостей. Проекты и счётчики берутся из `projects.js`. Форма отправляет заявку через серверную функцию `api/send.js`, ключи в браузер не попадают.

## Запуск на компьютере
1. Установите Node.js 22.9 или новее.
2. Откройте терминал в `dev-portfolio`.
3. Скопируйте `.env.example` в `.env`. Для проверки настоящей отправки заполните переменные (см. ниже). Без них витрина работает, форма честно сообщает о недоступности.
4. Запустите `npm run dev` и откройте http://127.0.0.1:4173.
5. Проверки: `npm run check` и `npm test`. Тесты используют заглушку Telegram, реальные сообщения не отправляются.

## Как разместить на Vercel
1. Создайте Git-репозиторий с содержимым этой папки. Перед push проверьте файлы на секреты. `.env` не должен попадать в Git.
2. В Vercel нажмите **Add New → Project → Import Git Repository**.
3. Если репозиторий содержит несколько проектов, укажите **Root Directory: dev-portfolio**. Если загрузили только эту папку, оставьте корень репозитория.
4. Выберите **Framework Preset: Other**, Node.js 22.x или новее. Команда сборки `node prepare.js`, каталог результата `public` уже указаны в `vercel.json`. Функция `api/send.js` разворачивается отдельно.
5. В **Settings → Environment Variables** добавьте `BOT_TOKEN` и `CHAT_ID` для Production (и Preview, если нужна работа формы в превью).
6. Нажмите **Deploy**. После изменения переменных нажмите **Redeploy**. Откройте опубликованный сайт и отправьте тестовую заявку.
7. При желании подключите свой домен в **Settings → Domains**.

Официальная документация: [конфигурация проекта](https://vercel.com/docs/project-configuration), [серверные функции Node.js](https://vercel.com/docs/functions/runtimes/node-js).

## Telegram
- `BOT_TOKEN` — токен вашего бота, созданного через официальный @BotFather.
- `CHAT_ID` — идентификатор чата получателя. Сначала откройте диалог с ботом и нажмите Start; для группы добавьте бота в неё. Идентификатор получите через Telegram Bot API `getUpdates` в доверенном инструменте, не вставляя токен в публичные сервисы.
- На локальном компьютере ключи хранятся только в `.env`, на Vercel — только в переменных окружения. `.env.example` намеренно содержит пустые значения. Не присылайте ключи посетителям и не добавляйте их в `projects.js`.

## Добавление проекта за 30 секунд
Вверху `projects.js` есть инструкция. Скопируйте объект, замените название, ссылку, описание, категорию и теги. Сохраните скриншот в `assets/` и укажите путь в `image`. Категория должна точно совпадать с одной из трёх существующих. Без скриншота появится оформленная заглушка. Счётчик и фильтры обновляются автоматически; после изменения файлов опубликуйте новую версию на Vercel.

## Что можно менять
- `index.html`: тексты, цены, Telegram-ссылка `https://t.me/wertbst`.
- `style.css`: цвета и оформление; основные переменные в `:root`.
- `projects.js`: все данные портфолио.
- `api/send.js`: серверная валидация и содержание сообщения. При изменении типов услуг синхронно обновите список в HTML и TYPES на сервере.

## Защита и ограничения
Сервер принимает только POST JSON, ограничивает размер, проверяет имя, телефон/Telegram, тип услуги и honeypot. Запросы браузера с другого домена отклоняются. При заполнении ловушки сообщение в Telegram не отправляется. На ошибку Telegram посетитель получает понятный ответ без технических данных и секретов. Статическая сборка включает только публичные файлы.

Honeypot не заменяет полноценный антибот: при массовом спаме включите ограничения запросов в Vercel Firewall. Сайт не подключает оплату, аналитику и базу данных. Google Fonts загружаются извне, при недоступности работают системные шрифты. Сроки и итоговый объём работ уточняются при обсуждении проекта. Реальная отправка требует ваших переменных окружения.
